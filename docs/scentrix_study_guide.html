Scentrix Study Guide

1. What Is Scentrix

One-line pitch: A reproducible full-stack research platform demonstrating that graph construction methodology — not model architecture — is the critical determinant of GNN performance in cold-start recommendation, using luxury fragrance discovery as the domain.

Problem

Cold-start recommendation with zero user interactions. Catalog turns over frequently; new releases lack ratings. Collaborative filtering fails entirely; content-based methods hit a ceiling.

Dataset

~5,000 quality-filtered fragrance items (from 22,740). 24 brands, 48 accord categories. Filtered via quality gates in filter_elite.py — complete note profiles, valid brand, non-empty accord lists.

Stack

5 Docker containers: PostgreSQL 15 (relational), Neo4j 5 (knowledge graph), Redis 7 (cache), FastAPI backend (Python 3.11+), Next.js 16 frontend. Plus offline PyG evaluation pipeline.

Key Finding

Embedding-derived KNN graph causes 63% relative NDCG degradation vs Jaccard-corrected baseline (0.183 vs 0.494). Replacing circular edges with structurally independent Jaccard similarity recovers 2.7× improvement (p≤0.001, d=0.93).

2. The Research Claim

Locked claim (CHANGELOG):

"Graph construction methodology is the critical determinant of GNN performance in cold-start recommendation. Embedding-derived similarity graphs introduce feature circularity that degrades NDCG by 63% relative to independent baselines. Replacing circular edges with structurally independent Jaccard similarity over fragrance notes recovers 2.7× performance improvement (NDCG 0.183 → 0.494, p≤0.001, d=0.93)."

GraphSAGE-Jaccard NDCG@10=0.504 vs GraphSAGE-Embedding NDCG@10=0.197. 63% relative degradation. Feature-Only (0.557) beats GraphSAGE-Jaccard — graph claim is scoped to structural independence, not absolute performance.

In plain English: If you build the graph edges using the same embedding vectors that are also the node features, the GNN just aggregates neighbors that are already maximally similar — it learns nothing new and actually performs worse than raw cosine similarity. If instead you build edges using an independent signal (fragrance note overlap), the GNN gets useful structure to learn from. The claim is not "GNN beats content-based methods" — it doesn't. The claim is that how you build the graph matters more than which model you use.

4. The Evaluation Pipeline

Cold-Start Split Logic

  • Stratified 80/20 split — 80% warm (training), 20% cold (evaluation), stratified by primary accord
  • 920 cold items held out; 77 excluded with zero relevant ground-truth neighbours
  • 843 evaluated cold items — all share the same split across all model evaluations
  • Cold items are completely removed from training — no transductive leakage

Ground Truth Construction

Two criteria, both independent of the embedding space:

  1. Primary accord match — cold item i and warm item j share the same primary accord
  2. Jaccard note overlap > 0.20 — one-sided minimum floor, not an exact threshold match
Caveat. The ground-truth Jaccard floor (0.20) matches the graph edge threshold for GraphSAGE-Jaccard. This is an acknowledged design choice, not evaluation circularity — GraphSAGE never sees ground truth during training, and ground truth uses no embedding signal. However, it does favour methods whose inductive bias aligns with Jaccard note overlap.

6. Three Core ML Problems and Fixes

1. Cross-Modal Feature Mismatch

Problem: 432-dim feature vector concatenates accord one-hot (48) + Sentence-Transformer embedding (384). These are different modalities — sparse categorical vs dense semantic. The GNN must learn to balance them, and naive concatenation can cause one modality to dominate.

Fix: InfoNCE contrastive loss (tau=0.5) with cosine similarity naturally handles multi-modal features by normalising the representation space. Edge dropout (0.1) prevents overfitting to dominant dimensions.

2. Representation Degeneracy

Problem: With embedding-derived KNN edges, the GNN aggregates neighbours that are already maximally similar. The representations collapse toward a neighbourhood mean that carries no new information — the model performs worse than raw features (NDCG 0.197 vs Feature-Only 0.557).

Fix: Replace with structurally independent Jaccard edges over notes. The graph now carries signal orthogonal to the embedding space, so aggregation learns something new. NDCG recovers to 0.504 — a 2.7× improvement.

3. Topological Islands

Problem: Degree-0 cold items have no incident graph edges — the GNN cannot infer representations for them. At threshold 0.20, only 7/843 cold items are degree-0 (99.2% coverage), but at 0.30, coverage drops to 65.4% (551/843).

Fix: Feature-only fallback for degree-0 nodes: if a cold node has no edges, use raw cosine similarity on the 432-dim features. Group B NDCG is 0.255 at 0.20 threshold (7 items) and 0.317 at 0.30 (292 items).

7. quiz_init — What It Is & Why It Doesn't Beat pure_cold

What it is: A simulated quiz-based preference signal that injects user responses into the recommendation pipeline. Instead of pure cold-start (no user signal), the system asks the user quiz_length questions, builds a confidence vector, and reranks GraphSAGE predictions via alpha-blending.

Architecture (final):

  • quiz_rerank_pool=50 — predict_cold_start retrieves top-50 candidates
  • Alpha blend: blended = (1-α) × rank_score + α × quiz_score
  • rank_score = 1 − (rank / total), normalised over pool of 50
  • Top-10 truncation after reranking for metric computation
  • quiz_alpha=0.3 default in EvalConfig

  • GraphSAGE-Jaccard follows the expected monotonic trend: higher warmth → better NDCG
  • GraphSAGE-Embedding is non-monotonic: drops from Level 0 (0.198) to Level 1 (0.161) before recovering at Level 2 (0.229). This reflects its connectivity weakness — low-popularity items have sparser embedding-similarity neighbourhoods

Leakage caveat: Levels 1 and 2 evaluate warm items using a model trained on the full warm set. This introduces data leakage — per-stratum scores are optimistic. A leakage-free evaluation would require separate model training per stratum. This is explicitly left as future work in the paper.

10. Interview Questions with Model Answers

What is the single most important finding of your research?
That graph construction methodology determines GNN cold-start performance more than model architecture. When you build graph edges from the same embedding space used as node features, the GNN aggregates neighbours that are already maximally similar — it learns nothing new and actually performs worse than raw feature similarity. Replacing circular edges with structurally independent Jaccard similarity over fragrance notes recovers a 2.7× improvement (NDCG 0.183 → 0.494, p≤0.001, d=0.93).
Why doesn't GraphSAGE beat Feature-Only? Doesn't that invalidate your GNN approach?
Feature-Only scores 0.557 NDCG vs GraphSAGE-Jaccard's 0.504, but this comparison is not the paper's contribution. Feature-Only is a near-oracle baseline: it uses the same 432-dim embedding space that partially encodes the ground truth criterion (Sentence-Transformer embeddings derived from descriptions that include note names). The meaningful comparison is GraphSAGE-Jaccard vs GraphSAGE-Embedding — same model, different graph, 2.7× improvement. Moreover, Feature-Only hits its ceiling on day one — it has no mechanism to incorporate user interactions. GraphSAGE-Jaccard provides an extensible foundation that can scale with data via user-item edges, temporal dynamics, and multi-hop semantics.
Explain feature circularity like I'm a first-year CS student.
Imagine you're studying for a test with a group of friends. If you only study with people who already think exactly like you, your group discussion just repeats what you already know. You don't learn anything new. That's the embedding-derived KNN graph — it connects items that are already maximally similar in the embedding space, so the GNN's aggregation step is destructive. Jaccard similarity over notes is like studying with people from different backgrounds — you get genuinely new information. The result: NDCG jumps from 0.197 to 0.504.
How did you construct the ground truth, and is it circular?
Two criteria, both independent of the embedding space: (1) primary accord match, and (2) Jaccard note overlap > 0.20 (one-sided floor, not an exact threshold). No embedding signal is used. The ground-truth Jaccard floor does coincide with our graph edge threshold (0.20), which is an acknowledged design choice — but GraphSAGE never sees ground truth during training, and the Jaccard criterion is a similarity floor, not an exact match. The overlap is a limitation we explicitly disclose in Section V-C.
Why 7 baselines? Couldn't you have used fewer?
GraphSAGE-Embedding: isolates graph construction effect (same model, different graph). Feature-Only: near-oracle content baseline. Content-Only: oracle upper bound (uses exact ground truth criterion). Popularity & Random: establish performance floor. Quiz-init GraphSAGE: tests whether preference signal improves cold-start. Each baseline answers a specific question. Removing any of them would leave an unanswered question in the ablation chain.
What's the difference between Level 0, 1, and 2 stratification, and what did you learn?
Level 0 (true cold-start, 0 interactions, n=920), Level 1 (1-3 implied interactions, n=1,819), Level 2 (4+ interactions, n=1,820). GraphSAGE-Jaccard and Feature-Only show the expected monotonic trend — more warmth → better NDCG. But GraphSAGE-Embedding is non-monotonic: it drops from 0.198 (Level 0) to 0.161 (Level 1) before recovering to 0.229 (Level 2). This reveals that the embedding-derived graph has inconsistent connectivity for low-popularity items — a weakness hidden without stratification. Caveat: Levels 1-2 have data leakage (trained on full warm set), so scores are optimistic.
Quiz_init doesn't beat pure_cold. Why include it in the paper?
Negative results are valuable. Quiz_init showed that even with a preference-signal reranker (alpha=0.3, pool=50), simulated quiz data does not reliably beat pure cold-start — mean NDCG 0.496 vs 0.504, beats baseline only 2/5 seeds. This tells us that simulated quiz signal is insufficient and real user interaction data is needed. Publishing this negative result demonstrates intellectual honesty and sets clear expectations for future work.
What was the most significant bug you found during development?
Three pipeline functions — _run_quiz_init, run_quiz_sensitivity, and run_ablation_study — were using build_similarity_graph (embedding-derived KNN) instead of build_jaccard_graph. This meant quiz_init and ablation results were contaminated with circular edges. Only _run_warm_reference correctly used the embedding graph. Fixing this bug changed quiz_init NDCG significantly and corrected our ablation results, reinforcing the paper's central claim about graph construction importance.
How do you ensure your results are reproducible?
Single command: python -m ml.eval.pipeline --mode pure_cold --seed 42 (canonical seed). All metrics via ranx with locked evaluation parameters. CHANGELOG.md is the source of truth — every decision is committed with shell output verification. The demo package ZIP includes both model checkpoints, config, splits, and README with exact reproduction steps. Docker-compose for full stack.
Why Jaccard threshold 0.20 specifically?
It's the Pareto-optimal point in the edge quality vs coverage tradeoff. At 0.20, we get 16,244 edges with 99.2% cold-item coverage (836/843 have graph connections, only 7 are degree-0). Group A NDCG is 0.494. Going stricter (0.30) gives better quality (Group A NDCG=0.642) but coverage drops to 65.4%. Going looser (0.10) gives full coverage but Group A NDCG drops to 0.432. The tradeoff is quantified in the threshold sweep table.
What would you do differently if you had 6 more months?
(1) Scale evaluation to the full 22,740-item catalog. (2) Cross-domain validation — wine, books, music — to prove circularity is domain-agnostic. (3) Collaborative user-item graph with real interaction data. (4) Leakage-free stratification (separate model training per stratum). (5) Extend quiz_init with adaptive quiz strategies and real human-subject evaluation.
How does your work relate to PinSage and NGCF?
PinSage and NGCF focus on model architecture for web-scale or collaborative recommendation. My work focuses on graph construction methodology — a dimension those papers treat as a preprocessing detail. The key finding (edge construction > model architecture) is complementary: you could apply PinSage's random-walk sampling or NGCF's embedding propagation on top of our Jaccard graph and likely see further gains. The contribution is diagnostic, not architectural.
What makes this a MEXT-worthy project rather than just a class project?
Three things: (1) Novel diagnostic contribution — feature circularity in graph construction is not previously isolated in cold-start recommendation literature. (2) Reproducible infrastructure — 5 Docker containers, locked evaluation pipeline, single-command reproduction. MEXT values open science. (3) Intellectual honesty — negative results (quiz_init, Feature-Only comparison) are fully reported with statistical rigor (bootstrap, Cohen's d). The project is designed as a research platform, not a one-off experiment.
Explain the threshold sweep in detail.
Five Jaccard thresholds: 0.10, 0.15, 0.20, 0.25, 0.30. For each, rebuild the graph, retrain GraphSAGE on warm edges, evaluate on cold items split into Group A (has edges) and Group B (degree-0 fallback). At 0.10: 21,452 edges, full coverage, Group A NDCG=0.432. At 0.20: 16,244 edges, 99.2% coverage, Group A NDCG=0.494. At 0.30: 6,341 edges, 65.4% coverage, but Group A NDCG=0.642. The monotonic rise in Group A NDCG is genuine — degree-split analysis confirms it's not fallback inflation. Stricter thresholds produce fewer but higher-quality edges.
What is the role of the Neo4j knowledge graph in the ML pipeline?
In the live stack, Neo4j powers real-time graph queries — note overlap, accord paths, brand relationships. But the evaluation pipeline is offline: it loads a static catalog from JSON, not from Neo4j at runtime. The knowledge graph was used during development to explore the data and validate note/accord relationships. A production deployment of Scentrix would use Neo4j for live recommendation serving, but the published results are computed from the frozen evaluation pipeline for reproducibility.
If a reviewer says "your NDCG values are low (0.5 range)", how do you respond?
NDCG@10 of 0.5 is not low for pure cold-start recommendation with zero user interactions. Compare: Random baseline scores 0.021, Popularity scores 0.008. The absolute NDCG scale in cold-start settings is fundamentally different from warm collaborative filtering (where NDCG can reach 0.8+). The relevant comparison is against baselines under identical conditions, not against warm CF numbers. Our baselines establish this: 0.504 represents a 24× improvement over Random (0.021) and 63× over Popularity (0.008).
