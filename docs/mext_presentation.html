The problem: New user, zero ratings, zero purchases, zero clicks. Collaborative filtering and matrix factorization produce nothing — they require user-item interactions that do not exist at cold start. Popularity (0.000 NDCG) performs identically to random guessing.

Fragrance is a pure cold-start domain — each discovery is an independent decision with no prior history to draw from.

Graph Construction

Jaccard similarity over shared note ingredients. Threshold 0.20 → 16,244 edges covering 99.2% of the catalog. 64-dim GraphSAGE embeddings trained via unsupervised link prediction.

5-State Dispatcher

Anonymous → Popularity. Quiz → GraphSAGE (USER_VECTOR). Cold → Hybrid β-blend. Warm → Feature-Based. Mature → Feature + Diversity. Graceful degradation at every state.

Key design: GraphSAGE is a preference initialization layer, not a standalone recommender. It sits alongside a feature-based scorer; a dispatcher selects the strategy by user signal level.

Two Hidden Flaws in Our Evaluation Pipeline

The claimed 2.7× improvement was entirely artifact

Fix A Metric Bug

NDCG@10 was RR@10. Reciprocal rank stops accumulating after the first relevant item found. True NDCG accumulates gains across all 10 positions with logarithmic discounting. This overestimated any model that placed one result high — nearly all models in cold-start evaluation.

Fix B Circular Ground Truth

Same signal for graph and evaluation. The original GT defined relevance as note-Jaccard >0.20 — the same function and threshold used to build the GraphSAGE graph. The model was evaluated against itself. Fixed with brand + accord: brand is independent of note chemistry; accord agreement is perfumer-labeled, not structural.

Effect when both fixes applied: The claimed 2.7× NDCG improvement disappeared entirely. Feature-Only — zero machine learning, simple accord overlap — outperformed GraphSAGE by 3.47×.

GT Sensitivity: 4 alternative definitions tested. Feature-Only leads under every non-circular variant. Brand_accord selected as strictest (31.7% coverage).

Secondary Contribution: The Data Audit
That Found a Better Pipeline

The frontend sent rich ratings (1–10) for nine months; the backend discarded them

Old: Centroid Path

Quiz confidence → 5 accord seeds → weighted centroid of seed embeddings → KNN. Threw away 90% of the signal: only binary liked/disliked was used, continuous 1–10 ratings were ignored.

New: USER_VECTOR

Rating-weighted mean of GraphSAGE item embeddings: Σ((ratingᵢ/10) × embeddingᵢ) / Σ(ratingᵢ/10). Every rating is a weight. No accord mapping, no centroid, no information loss.

Not a model innovation — a data utilization fix. Discovered because the evaluation audit forced examination of every data flow stage. The centroid path and USER_VECTOR use identical embeddings; the 41.4% gain comes entirely from using rating weights that were previously discarded.

Research Contributions

Five distinct findings spanning methodology, domain knowledge, and architecture

  • 1Evaluation leakage discovery (primary): Exposed circular ground truth in graph-based cold-start evaluation — Jaccard graph and Jaccard GT share the same signal. A structural vulnerability likely present in other published results.
  • 2Fix A — Metric correction: Identified and corrected RR@10 → true NDCG@10. RR systematically overestimates models that rank one item high and fail thereafter.
  • 3Fix B — Non-circular GT: Introduced brand + accord agreement as cross-signal GT. Brand is independent of note chemistry; accord agreement is functional. Methodology generalizable to any domain with independent signals.
  • 4USER_VECTOR discovery: Rating-weighted embedding mean outperforms centroid path by +41.4% NDCG. Discovered through data utilization audit — the signal was always there but being discarded.
  • 55-state architecture: Production state machine dispatching by user signal level with graceful degradation. Supporting evidence that research findings translate to a deployed service.
Primary contribution is methodological, not architectural: The field needs to audit evaluation methodology before believing model performance claims.

Evaluation Methodology > Model Complexity

"We built a GraphSAGE recommender. We found evaluation leakage. We corrected it. After correction, a simple feature-based method outperformed our GNN by 3.47×.

That negative result is the contribution — because it tells the field: before asking what model to use, first ask whether you are measuring the right thing."

Limitations

Single domain (fragrance). Embedding graphs are inherently feature-circular. No real user study — simulated leave-cold-out. Quiz reranker not re-evaluated under Fix B.

Future Work

Port to feature-sparse domain (images, audio). Centroid disagreement analysis (instrumentation deployed). Real user A/B test. Meta-evaluation of published cold-start results.
